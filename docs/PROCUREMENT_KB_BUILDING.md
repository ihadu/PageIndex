# 采购评分项知识库构建方案 - 企业落地指南

## 一、问题分析

### 当前知识库的局限性

| 局限 | 影响 |
|-----|------|
| 手动定义，覆盖有限 | 仅支持9种评分项，无法覆盖所有采购场景 |
| 静态关键词 | 不同行业/地区采购规则变化时无法适应 |
| 缺乏行业差异 | 建筑、IT、医疗、农业等不同行业评分项差异大 |
| 无验证机制 | 关键词是否准确无法验证 |
| 维护困难 | 新增/修改需要手动编辑代码 |

### 企业落地挑战

```
挑战1：采购类型多样性
├── 政府采购（货物、服务、工程）
├── 企业采购（招投标、竞争性谈判）
├── 国际采购（不同国家规则）
└── 行业采购（建筑、IT、医疗、农业...）

挑战2：评分项差异性
├── 货物类：价格、质量、售后服务、交货期
├── 服务类：人员、业绩、技术方案、服务方案
├── 工程类：资质、业绩、技术、安全、质量
└── 不同组合：混合采购评分项组合复杂

挑战3：关键词动态性
├── 新法规出台 → 评分项变化
├── 新证书类型 → 证明材料变化
├── 地区差异 → 关键词表述不同
└── 时间推移 → 知识库需持续更新
```

## 二、企业级知识库架构

### 分层架构设计

```
┌─────────────────────────────────────────────────────────────────┐
│ Layer 0: 基础知识库（通用层）                                     │
│ - 通用评分项定义（人员、业绩、资质、价格...）                      │
│ - 通用证明材料类型（证书、合同、发票...）                          │
│ - 来源：国家标准、采购法规                                        │
└─────────────────────────────────────────────────────────────────┘
                              ↓ 继承/扩展
┌─────────────────────────────────────────────────────────────────┐
│ Layer 1: 行业知识库（行业层）                                     │
│ - 建筑：施工资质、安全生产许可证、项目经理证书                     │
│ - IT：软件资质、系统集成资质、信息安全认证                         │
│ - 医疗：医疗器械资质、GMP认证、执业许可证                          │
│ - 农业：农药经营许可、植保无人机操作证                            │
│ - 来源：行业协会、行业法规                                        │
└─────────────────────────────────────────────────────────────────┘
                              ↓ 继承/扩展
┌─────────────────────────────────────────────────────────────────┐
│ Layer 2: 项目知识库（项目层）                                     │
│ - 特定项目评分项（根据采购文件提取）                               │
│ - 特定关键词（根据招标文件实际表述）                               │
│ - 特定证明材料（根据评分标准要求）                                 │
│ - 来源：从采购文件自动提取                                         │
└─────────────────────────────────────────────────────────────────┘
                              ↓ 动态调整
┌─────────────────────────────────────────────────────────────────┐
│ Layer 3: 自适应层（动态层）                                       │
│ - 从响应文件摘要中自动发现新关键词                                 │
│ - 从历史检索结果中优化关键词权重                                   │
│ - 从用户反馈中调整映射关系                                        │
│ - 来源：运行时自动学习                                            │
└─────────────────────────────────────────────────────────────────┘
```

## 三、知识库构建方法

### 方法一：标准法规解析（自动化）

```
输入：采购法规/评分标准文档
      ┌─────────────────────────────────┐
      │ 《政府采购货物和服务招标投标管理办法》│
      │                                  │
      │ 评分标准：                        │
      │ 1. 价格分（30分）                  │
      │ 2. 技术分（40分）                  │
      │    - 技术方案（20分）              │
      │    - 人员配备（10分）              │
      │    - 类似业绩（10分）              │
      │ 3. 商务分（30分）                  │
      └─────────────────────────────────┘
                        ↓ LLM解析
      ┌─────────────────────────────────┐
      │ 知识库结构化输出：                 │
      │                                  │
      │ {                                │
      │   "价格响应": {...},              │
      │   "技术方案": {...},              │
      │   "人员配备": {...},              │
      │   "类似业绩": {...},              │
      │   "商务方案": {...}               │
      │ }                                │
      └─────────────────────────────────┘

优势：
- 自动化程度高
- 标准化、规范化
- 覆盖面广

局限：
- 证明材料关键词需要人工补充
- 特殊表述可能遗漏
```

### 方法二：历史文件分析（数据驱动）

```
输入：历史采购响应文件（已标注页码）
      ┌─────────────────────────────────┐
      │ 响应文件A：                      │
      │   人员配备 → 85-89页（标题+操作证） │
      │   类似业绩 → 64-79页（标题+合同）  │
      │                                  │
      │ 响应文件B：                      │
      │   人员配备 → 32-35页（标题+培训证） │
      │   类似业绩 → 45-52页（标题+验收）  │
      └─────────────────────────────────┘
                        ↓ 分析统计
      ┌─────────────────────────────────┐
      │ 关键词统计：                      │
      │                                  │
      │ "人员配备"标题页关键词：           │
      │   - "人员配备" (85%)              │
      │   - "人员配置" (45%)              │
      │   - "作业人员" (30%)              │
      │                                  │
      │ 证明材料关键词（操作证类）：        │
      │   - "操作手合格证" (90%)          │
      │   - "无人机操作证" (60%)          │
      │   - "飞手证" (25%)                │
      │   - "培训证书" (40%)              │
      └─────────────────────────────────┘

优势：
- 关键词来源于实际文件
- 统计权重反映重要性
- 持续优化

局限：
- 需要标注数据
- 新类型可能未覆盖
```

### 方法三：专家知识注入（人工补充）

```
输入：采购专家/评审专家经验
      ┌─────────────────────────────────┐
      │ 专家经验：                       │
      │                                  │
      │ "评审人员配备时，我会检查：        │
      │  1. 操作证是否有效               │
      │  2. 人员数量是否满足              │
      │  3. 岗位分工是否合理              │
      │  4. 特殊工种是否有资质            │
      │                                  │
      │ 证明材料包括：                    │
      │  - 操作手合格证（大疆/极飞）      │
      │  - 培训合格证                    │
      │  - 职称证书                      │
      │  - 健康证明（某些项目需要）        │
      │  - 身份证复印件                  │
      │ "                                │
      └─────────────────────────────────┘
                        ↓ 结构化提取
      ┌─────────────────────────────────┐
      │ 补充知识库：                      │
      │                                  │
      │ material_types: {                │
      │   "健康证明": {...},  ← 新增      │
      │   "身份证": {...},    ← 新增      │
      │ }                                │
      └─────────────────────────────────┘

优势：
- 专家经验准确
- 补充遗漏材料类型
- 覆盖特殊场景

局限：
- 人工成本高
- 需要领域专家
```

## 四、推荐的企业落地流程

### 阶段一：基础知识库初始化

```python
# Step 1: 从采购法规提取基础评分项
from procurement_kb_builder import RegulationParser

parser = RegulationParser()
base_kb = parser.extract_from_regulation(
    "政府采购货物和服务招标投标管理办法.pdf"
)

# 输出基础评分项（约20-30种）
base_kb.save("kb_base.json")

# Step 2: 行业扩展
industry_kb = IndustryKBBuilder(base_kb)
industry_kb.extend_for_industry("农业飞防服务")
industry_kb.save("kb_agriculture.json")

# Step 3: 专家补充
expert_kb = ExpertKBEnricher(industry_kb)
expert_kb.add_material_type("健康证明", keywords=["健康证", "体检证明"])
expert_kb.save("kb_agriculture_expert.json")
```

### 阶段二：项目知识库自动构建

```python
# Step 4: 从采购文件自动提取评分项
from procurement_kb_builder import TenderParser

tender_parser = TenderParser()
project_kb = tender_parser.extract_from_tender(
    "松滋市2026年小麦一喷三防飞防服务采购文件.pdf",
    base_kb=expert_kb  # 基于已有知识库
)

# 输出项目特定评分项
print(project_kb.requirement_types)
# ['人员配备', '类似业绩', '设备能力', '技术方案', '售后服务']

# Step 5: 证明材料关键词发现
from procurement_kb_builder import KeywordDiscovery

discovery = KeywordDiscovery(project_kb)
discovery.discover_from_summaries(
    page_summaries,  # 响应文件摘要
    requirement_type="人员配备"
)

# 发现新关键词
print(discovery.new_keywords)
# ['操作手合格证', '植保无人机操作证', '飞手证']
```

### 阶段三：持续优化与验证

```python
# Step 6: 历史数据分析
from procurement_kb_builder import HistoryAnalyzer

analyzer = HistoryAnalyzer()
analyzer.load_history("历史检索记录.csv")

# 统计关键词命中率
hit_rate = analyzer.calculate_hit_rate("人员配备", "操作手合格证")
# 0.85 (85%的响应文件中操作证页包含此关键词)

# Step 7: 验证与调整
validator = KBValidator(project_kb)
validator.validate_with_ground_truth(
    ground_truth_file="标注数据.json"
)

# 输出验证报告
validator.report()
# ┌─────────────────────────────────┐
# │ 人员配备检索准确率: 92%           │
# │ 遗漏页面分析:                    │
# │   - 第89页漏检率: 8%             │
# │   原因: "合格证"关键词权重不足    │
# │ 建议: 提升"合格证"权重           │
# └─────────────────────────────────┘
```

## 六、工具实现建议

### 建议开发的工具

```
工具1: RegulationParser（法规解析器）
├── 输入: PDF法规文件
├── 输出: 基础评分项结构
├── 技术: LLM + 规则解析
└── 价值: 自动化初始知识库构建

工具2: TenderParser（采购文件解析器）
├── 输入: 采购文件PDF + 基础知识库
├── 输出: 项目特定评分项
├── 技术: LLM + 知识库映射
└── 价值: 项目知识库自动构建

工具3: KeywordDiscovery（关键词发现器）
├── 输入: 页面摘要 + 评分项类型
├── 输出: 新证明材料关键词
├── 技术: 统计分析 + LLM归纳
└── 价值: 发现遗漏关键词

工具4: KBValidator（知识库验证器）
├── 输入: 知识库 + 标注数据
├── 输出: 验证报告 + 优化建议
├── 技术: 准确率统计 + 错误分析
└── 价值: 确保知识库准确性

工具5: KBManager（知识库管理器）
├── 功能: 版本管理、合并、导出
├── 技术: Git式版本控制
└── 价值: 知识库持续维护

工具6: KBEditor（可视化编辑器）
├── 功能: 可视化编辑、预览、测试
├── 技术: Web UI + 即时验证
└── 价值: 降低维护门槛
```

## 七、实施建议

### 分阶段实施

```
Phase 1 (1-2周): 基础知识库
├── 从法规提取基础评分项
├── 专家补充核心证明材料类型
├── 构建通用关键词库
└── 产出: kb_base.json

Phase 2 (2-4周): 行业知识库
├── 针对主要行业扩展
├── 分析历史文件补充关键词
├── 行业专家验证
└── 产出: kb_agriculture.json, kb_construction.json...

Phase 3 (持续): 项目知识库
├── 每个项目启动时自动构建
├── 从采购文件提取项目特定评分项
├── 关键词动态发现
└── 产出: kb_project_xxx.json

Phase 4 (持续): 自适应优化
├── 从检索结果自动学习
├── 用户反馈驱动调整
├── 定期验证与更新
└── 产出: 知识库版本迭代
```

### 优先级建议

| 优先级 | 任务 | 时间 | 价值 |
|-------|-----|------|------|
| P0 | 基础知识库（通用评分项） | 1周 | 覆盖80%场景 |
| P1 | 行业知识库（核心行业） | 2周 | 提升行业准确率 |
| P2 | 项目自动构建工具 | 2周 | 降低人工成本 |
| P3 | 可视化编辑器 | 3周 | 降低维护门槛 |
| P4 | 自适应学习 | 4周+ | 持续优化 |
